# 01: Dart API and Flutter DX implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give applications a small, predictable public API with an independent Dart core and explicit lifetime rules.

**Architecture:** Extract the existing implementation before changing behavior. Put scene values, scheduling and plugin contracts in `gpu3d`; put controller and widget ownership in `flutter_gpu3d`. Use one engine underneath managed, borrowed and offscreen consumers.

**Tech Stack:** Dart, Flutter 3.47.5, Rust 1.97.1, wgpu 30.0.1.

**Spec:** [Public API](../../design/native-3d-api.md), [output contract](../../design/native-presentation.md), [program](2026-09-26-native-3d-program.md).

## Global Constraints

- Render 3D through native Metal, Vulkan or Direct3D 12. Do not add WebGL, a WebView, JavaScript or an OpenGL renderer fallback.
- Keep geospatial an optional plugin. The general 3D core must never import geospatial.
- Target general 3D capabilities comparable to Three.js; do not claim JavaScript source compatibility or current feature parity.
- Keep scene data, geometry, materials, animation and plugin contracts usable from Dart without Flutter widgets.
- Use Flutter 3.47.5 and Rust 1.97.1 for development; keep Dart SDK >=3.10.0 <4.0.0 and Flutter >=3.38.0 declarations until a tested API requires a higher floor.
- Keep wgpu pinned to 30.0.1 while introducing native texture interoperability; review unsafe HAL code before changing that pin.
- Commit each verified task locally. Do not push or merge without a request.
- Keep shipped prose free of em dashes and attribution trailers.

## Review Focus

- Managed view removed while backend creation is pending: late creation is closed and readiness settles with `disposed`. Task 3.
- Nested transform edits followed by an exception: the final revision still causes one frame. Task 2.
- A borrowed controller remounts, or a second view tries to mount it: preserve scene state and reject concurrent attachment. Task 3.
- A pointer crosses a Flutter overlay at a noninteger device pixel ratio: preserve logical coordinates and gesture ownership. Task 4.
- Worker exit or plugin detach throws during cleanup: other owners still close, all pending requests settle, disposal remains idempotent. Task 5.

## Task 2: Observable scene values and on-demand scheduling

Implemented: immutable values, revision streams, batching and the core scheduler.
The Flutter controller in task 3 will consume this scheduler.

**Files:** Create `packages/gpu3d/lib/src/math/{vec3,quat,mat4,angle}.dart`,
`scene/revision.dart`, `rendering/frame_scheduler.dart`; modify scene, camera and
material modules. Create `packages/gpu3d/test/{scene_revision,frame_scheduler}_test.dart`.
Migrate geodesy value boundaries and planet transforms in the same change.

**Interfaces:** `Vec3`/`Quat`/`Mat4` are immutable double-precision values with
explicit `toVectorMath()` conversions returning copies. `Object3D.revision` is
monotonic; scene descendants notify their owning scene. `Scene.changes` is a
coalescible revision stream; `Scene.batch(void Function())` nests safely.
`FrameScheduler.request()`, `tick(Duration now) -> FrameTime?`,
`acquireDemand() -> Registration`, `setVisible(bool)` implement the clock contract.
`Registration.dispose()` is synchronous and idempotent.

- [x] Add a test that edits position, material, visibility and a nested child after an idle frame. Assert each change wakes the scheduler. Pin exception behavior with real scene values:

```dart
test('a failed batch still exposes its final mutation', () {
  final scene = Scene();
  final mesh = scene.add(Mesh(BoxGeometry(), UnlitMaterial()));
  final before = scene.revision;
  expect(() => scene.batch(() {
    mesh.position = const Vec3(4, 0, 0);
    throw StateError('application callback failed');
  }), throwsStateError);
  expect(mesh.position, const Vec3(4, 0, 0));
  expect(scene.revision, greaterThan(before));
});
```

- [x] Run `fvm dart test test/scene_revision_test.dart test/frame_scheduler_test.dart` in `gpu3d`; the new values/revision contract must initially fail. Include reparenting/cycle rejection, shared geometry used in two scenes, no writable matrix storage, radians and singular/nonfinite transform input.
- [x] Implement checked setters, parent propagation and notification batching with a `try/finally` depth counter. Keep IDs stable across transforms. Replace mutable material fields with `DiffuseMaterial`/`UnlitMaterial` descriptors and `copyWith`. Migrate `Scene.add` to return its argument. Preserve geodetic double precision and compare existing geodesy fixture values before/after conversion.

```text

  if hidden or neither dirty nor continuous demand: return null
  if FPS deadline has not arrived: retain dirty state; return null
  compute rawDelta from monotonic clock
  delta = zero on resume, otherwise min(rawDelta, 100 milliseconds)
  clear the submitted revision only; preserve mutations made during callbacks

```

**Interfaces:** Implement the constructor, readiness, status, `update`, `invalidate`,

- [x] Write widget tests that rebuild a managed view 20 times with the same `sceneKey` and assert one setup/session, then replace its key and assert reverse teardown before replacement attach. Use a controllable factory to test removal during initialization:

```dart

final controller = SceneController(
  runtime: SceneRuntime(backendFactory: () => pending.future),

  child: SizedBox(width: 64, height: 64,
    child: SceneView(controller: controller)),

    throwsA(isA<SceneException>().having((e) => e.issue.code, 'code', 'disposed')));

```

- [x] Run `fvm flutter test test/controller_test.dart test/managed_view_test.dart test/borrowed_view_test.dart` in the facade; missing controller behavior must fail. Add tests for borrowed unmount/remount, simultaneous attachment rejection, throwing `onCreate`, plugin attach failure, throwing error callbacks and capture/dispose overlap once capture is available in plan 02.
- [x] Implement a generation-based state machine. Start attachment after managed `onCreate` has registered plugins. `dispose()` synchronously marks closed and cancels subscriptions before asynchronous teardown. Use `finally` to close a backend arriving after cancellation. Give every readiness generation a success or typed error. Retry creates new readiness futures and does not replay `onCreate` or add duplicate scene nodes.

```text
attach(viewToken): reject another active token; acquire presentation; start engine
detach(viewToken): invalidate token; stop submissions; close its presentation
dispose(): reject work now; cancel scope; detach; close plugins/backend; settle whenDisposed
retry(): require failed state; close failed generation; recreate from retained CPU scene
```

## Exit gate

M0 is complete when both geospatial and Flutter consume the independent core,
all lifetime tests pass and the examples use the public API. Shared textures,
glTF, advanced shaders and PBR are separate milestones. Until M1 qualifies the
native adapter, runnable examples must select `readbackOnly` explicitly and show
that choice in their diagnostics.
