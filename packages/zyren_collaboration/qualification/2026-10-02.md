# Collaboration qualification, 2026-10-02

The requested presence, shared camera, durable storage, network, offline and
shared undo paths are implemented. Native verification covers macOS Metal on an
Apple M3 Max. These results do not qualify iOS, Android, Linux or Windows.

## Automated evidence

- All 46 Dart tests pass. They cover operation conflicts and receipts, host
  permissions, restart recovery, separate-process file writers, conditional
  undo/redo, HTTPS and WSS certificate validation, denied/revoked access, socket
  reconnect, offline file recovery after a lost acknowledgement, reviewed
  conflict identity, presence ordering/rate/expiry and shared agent actions.
- The native integration test passes with two `SceneView` instances. Both use
  `PresentationPath.nativeView` and report zero readback bytes. It runs HTTP and
  WebSocket clients against file storage, keeps Alice's view disconnected while
  offline, resolves a competing edit, invokes guarded undo through the shared
  registry, follows a leased camera and queries a rich logical-coordinate hit.
- The same native test passes with the external stdio MCP probe. The probe uses
  the existing `zyren_devtools` CLI and authenticated loopback bridge. It checks
  discovery, Metal adapter data, presented-frame context, source/runtime identity,
  a visibility command, duplicate retry, stale rejection, shared undo, presence
  and the outbox. See `committed-macos-metal-mcp.json` for structured evidence.
- Dart analysis and formatting pass. The repository package-boundary and Apple
  ABI header check passed earlier in the run. The final repeat is blocked by
  concurrent `zyren_pointclouds/lib/geospatial_agents.dart` imports of
  `zyren_geospatial` and `zyren_3d_tiles` outside its current allowlist. No
  collaboration boundary violation was reported. No package is published or pushed.

## Committed shared dependency check

The interaction adapter is committed in `828955b8`. Newer shared-package changes
were present during this work. To avoid relying on them, the final qualification
exported `zyren_agents` and `zyren_devtools` from that commit to a temporary tree.
All other package roots remained mapped to the current workspace.

All 46 Dart tests passed with the isolated package map. The MCP test asserted
that its resolved devtools library came from that temporary tree; the child CLI
resolved the same map. The native test and external probe also passed with it.
Flutter's generated Xcode configuration recorded that isolated `PACKAGE_CONFIG`.
The structured native evidence records the full shared source revision.

This proves compatibility with the committed shared agent/bridge code. It is not
an assertion that every other package in this concurrent checkout was clean.

## Visible layout check

The normal app was inspected through the native UI at 800 and 390 logical points

## Boundaries

Scene edits currently cover transforms and visibility on a pinned source object
set. Creation, deletion, reparenting and materials remain separate work. The
file store is a bounded ledger that replays on read. It supports cooperating
processes on a local filesystem with one owning isolate per process. It does not
provide directory fsync, power-loss durability, distributed locking or unlimited
history. Receipt capacity is explicit and old receipts are never silently evicted.

Offline queues allow one pending decision per object field and up to 256 edits.
Changed epochs and denied edits remain inspectable; they are not silently
migrated or dropped. Reconciliation cannot cancel a write already sent to a
remote authority. The in-process guarded path remains available for agent edits.

Presence expires rather than becoming durable history. Unexpected disconnects
remain visible until the lease ends. Camera following requires a host to poll
or react to invalidations, and stops locally on lease expiry or local navigation.
The WebSocket client reconnects on its next request; the example's heartbeat
provides that request while idle. Cross-server changes need polling or a host
notification bus.

Native frame IDs and presentation times are observed. Exact frame-to-scene
revision correlation and rendered-pixel hit visibility remain unknown. CPU
geometry queries do not establish either. Other devices and backend paths were
not tested in this workstream.
