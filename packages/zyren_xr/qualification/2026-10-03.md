## Review corrections

The Metal camera/depth, scene binding, placement guard and lighting reviews passed
after their focused fixes. The final example review passed after independent
cleanup attempts, stale UI invalidation and a tested disposal retry.

Android review identified presentation semaphore lifetime, failed-retirement
surface retention, imported-format validation, unrelated clock timebases, queued
lifecycle invalidation, obsolete surface callbacks, temporary anchor tracking and
delayed depth submission. Dart anchor recovery and clock metadata corrections are
committed and tested. Independent reviewers approved the native corrections in
`a3e9c1f`, including acquisition and presentation fences, retryable retirement,
immediate generation invalidation and the applied receipt after rejected publication.
Raycasts now validate host observation times separately from raw sensor times.
Native depth staging bytes survive the public diagnostics filter.

The resumed physical runs exposed Android host and surface issues. Commit `28b4f9c`
corrects ELF alignment, and `ee3e266` preserves a pending camera request through
its own permission dialog while still cancelling on stop/detach. Commit
`12615b5` defers swapchain creation while the Android window and camera viewport
sizes disagree, rejects superseded surface callbacks, and preserves the applied
scene receipt when an out-of-date drawable cannot be published. Twelve Kotlin
tests and independent native review cover these corrections.

The camera probe now waits for Flutter layout and native calibration to agree,
then checks every steady frame. Its first stricter run exposed a fatal extent
mismatch; the corrected native run passed. A repeat also demonstrated normal
platform-view callback lag, which the bounded convergence check now handles.
The host examples keep the display awake. The lifecycle probe is committed in
`0e384aa` and passes on both phones and iPad. The final camera probes check 31 steady
frames in each orientation against the actual Flutter viewport.

The iPad retry exposed the example's missing fullscreen setting. Commit
`222f0104` enables iPad orientation requests and keeps Flutter frames running in
the live native-agent probe. Its camera then passes both orientations. The old
black Pixel screenshots came from a probe that did not keep Flutter frames
running, so they do not establish a camera-import failure. The updated live view
shows a lit, plain ceiling, with ARCore reporting insufficient features.

Native ARKit raycasts also rejected calibration because its in-process dictionary
contained `CGFloat` dimensions where the raycast required `Double`. Commit
`092b11e1` gives calibration one serializer with explicit numeric types, covered
by a regression compiled against the production helper. The iPad native MCP flow
passes after this fix. Commit `03415c46` adds raycast status/message diagnostics
and an independent depth probe, which passes on iPhone and iPad. Independent reviews
approved these corrections.

The native-agent probe queries plane geometry when its hit contains a plane ID.
[ARKit's existing-plane target](https://developer.apple.com/documentation/arkit/arraycastresult/anchor)
supplies that anchor, so geometry coverage
in this pass follows from the native path and the conditional assertion. The log
does not separately record the plane ID or geometry counts. The Apple
retry logs also contain a non-fatal linearization/solving fallback warning. The
iPad depth run includes an unused-variable warning from the generated shader.

## Reproduce

Use `/Users/rexraphael/fvm/versions/3.47.5/bin/flutter` and its Dart executable.
From the workspace root:

```sh
flutter test --no-pub packages/zyren_xr/test packages/zyren_xr/example/test --reporter expanded
dart analyze packages/zyren_xr
```

From `packages/zyren_xr/example`, select an available physical device:

```sh
flutter drive --profile --no-pub --keep-app-running --driver=test_driver/session_driver.dart --target=integration_test/session_test.dart -d DEVICE_ID
flutter drive --profile --no-pub --keep-app-running --driver=test_driver/session_driver.dart --target=integration_test/presentation_test.dart -d DEVICE_ID
flutter drive --profile --no-pub --keep-app-running --driver=test_driver/session_driver.dart --target=integration_test/native_agents_test.dart -d DEVICE_ID
flutter drive --profile --no-pub --keep-app-running --driver=test_driver/session_driver.dart --target=integration_test/depth_test.dart -d DEVICE_ID
```

The native agent probe traverses the shared MCP codec and authenticated HTTP
loopback listener. The full flow passes on iPad; both phones pass its
discovery/inspect/denial stage. The separate host stdio bridge is
`example/tool/mcp.dart`.

The independent depth probe prints `XR_NATIVE_DEPTH_PRESENTATION_PASS` after
16 depth-enabled frames, then `XR_NATIVE_DEPTH_STALE_RECOVERY_PASS` after stale
lease rejection and a successful fresh frame. You do not need a detected plane
for this probe. It does not measure foreground occlusion or confidence filtering.

Run `integration_test/lifecycle_test.dart` for retained-frame invalidation. After
`XR_LIFECYCLE_BACKGROUND_READY`, background the app until it reaches the paused
state, then return to the same process. The probe verifies explicit restart and
prints `XR_LIFECYCLE_RETAINED_FRAME_RESTART_PASS` on success.

See [Android setup](../android/README.md) for Vulkan requirements and the explicit
permission probe. Environment probes, persistent/cloud anchors, HDR/wide-gamut
qualification and headset implementation remain outside the current mobile work.
