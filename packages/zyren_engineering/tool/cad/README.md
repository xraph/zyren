# CAD review bundles

Convert IFC, STEP or IGES into a native-renderable GLB and a pinned source-identity
sidecar. You need Python 3.11 and the packages in `requirements.txt`.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python convert.py source.ifc output-bundle
.venv/bin/python -m unittest discover -p test_convert.py
```

Run each conversion in a fresh process. IfcOpenShell and OCP package their own
OpenCascade runtimes; loading both into one Python process is unsupported.
The Flutter example starts the converter as a subprocess.

The output directory contains `model.glb` and `review.json`. Its SHA-256 digest
pins the hierarchy paths to that exact GLB. `EngineeringCadBundle.read` verifies
the digest before the app imports geometry. Publication uses a directory rename;
choose a new output path for each revision. Existing nonempty bundles are kept.

## Identity and units

IFC uses the authored `GlobalId`, converts geometry to metres, and preserves
object placement separately from local geometry. Names are labels. Renaming a
part or changing its placement keeps the source ID and its local review anchors.
Geometry processing uses [IfcOpenShell](https://docs.ifcopenshell.org/ifcopenshell-python/geometry_processing.html).

STEP and IGES use [OpenCascade](https://dev.opencascade.org/doc/overview/html/occt_user_guides__step.html)
for transfer and tessellation. Supply the scale of the *transferred* coordinates
in metres per unit, plus an explicit identity map:

```json
{
  "schemaVersion": 1,
  "objects": [
    {"selector": "step:PUMP-HOUSING", "id": "pump-housing", "label": "Housing"}
  ]
}
```

```sh
.venv/bin/python convert.py housing.step output-bundle \
  --identity-map identities.json --meters-per-unit 0.001 --deflection 0.1
```

A STEP selector uses the authored product ID of a transfer root. An IGES selector
uses its authored short label and subscript, for example `iges:PUMP:7` (use `-1`
when no subscript exists). Missing, duplicate and unused selectors fail the
conversion. You cannot use an export's row number or a display name as a fallback.
Keep this mapping with the source model. The exporter must preserve these keys.

The review granularity is one object per transfer root. Nested STEP assembly
members are tessellated within that root, not exposed as separate review objects.
Export separate roots when you need separate part reviews. Surface-only IGES is
supported when its roots have authored labels. Unlabelled roots are rejected.
STEP/IGES deflection is measured in transferred source units; verify a known
measurement before reviewing a new exporter configuration.

Native SolidWorks, Revit and other proprietary files require their vendor's IFC,
STEP or IGES exporter. This tool does not parse those native formats. It imports
geometry, source keys, labels and format metadata; it does not preserve parametric
features, materials, PMI, every property set or editing history.

## Limits and checks

Sources are limited to 256 MiB, output to 10,000 roots and two million triangles,
and sidecars to 2 MiB. Parser failures leave the existing bundle untouched.
These limits do not sandbox native parsers. Run untrusted conversions in your
own constrained worker process or container with CPU and memory limits.

Tests create actual IFC, STEP and IGES files, tessellate them and check identity,
units, placement, rejected mappings and atomic output. The Dart tests load the
checked-in IFC bundles through `zyren_gltf` and verify annotations after reload.
The fixtures are generated by `test_convert.py`; `moved.ifc` keeps the GlobalId
while changing the name and translating the object three metres along X.
