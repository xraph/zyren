# Section tools qualification, 2026-10-02

You can use caps for closed concave shells, disconnected shells, nested cavities
and transformed instances. Invalid topology and complexity limits produce a
diagnostic instead of a partial cap. The workbench exposes caps and live handle
visibility controls.

## Checks that passed

- 73 tools tests, including contour area, multiple cuts, distant coordinates,
  reflected instances, eligibility caching and runtime gizmo visibility.
- 15 workbench widget tests. Section controls were checked at 1100, 390 and 320
  logical pixels.
- 20 native regression tests, followed by two additional instance pixel and
  resource cleanup tests. Both depth conventions passed on macOS Metal.
- The macOS integration test passed with 40 presented frames, an 864 by 484
  viewport, working caps and overlay controls, and zero presentation readbacks.
  Its separate offscreen checks deliberately read pixels to verify custom shader
  clipping, concave caps and cavity caps under both depth conventions.

The CPU benchmark is saved in `../benchmarks/macos-arm64.json`. It measures the
builder, including 65,024 source triangles. These measurements do not establish
interactive frame rates. You should use the documented geometry and work limits
when choosing cap targets.

## Device blockers

Android: the APK built and installed on the connected Pixel 9 Pro (Android 17,
API 37), but the process crashed during native startup. The two symbolized frames
were `__bionic_getauxval` and `init_have_lse_atomics`. The test did not complete;
this does not establish Android renderer or tools support.

iPhone: the signed build completed, but the wireless launch did not expose its
Dart VM service after 75 seconds. The run was stopped. You need a working debug
connection before this test can establish iOS support.

Windows and Linux: no execution host was available for runtime qualification.
Neither platform has a passing result in this record.

## Reproduction

Use Flutter 3.47.5 for the workbench. From `examples/multiple_views`, run:

```sh
flutter test integration_test/section_tools_qualification_test.dart -d macos
flutter test integration_test/section_tools_qualification_test.dart -d DEVICE_ID
flutter drive --driver=test_driver/qualification.dart --target=integration_test/section_tools_qualification_test.dart -d IPHONE_ID --publish-port
```

From `packages/zyren_native`, run the native contour checks with a GPU available:

```sh
RUN_NATIVE_GPU=1 flutter pub run test:test test/section_contours_test.dart
```

The tests require a real native backend. They do not substitute a browser renderer
when native initialization fails.
